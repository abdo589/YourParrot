# ببغاوتك — YourParrot 🦜

متجر إلكتروني سعودي (عربي RTL) لبيع الببغاوات ومستلزماتها، مبني بـ **Next.js 16 + React 19 + TypeScript + Tailwind CSS 4**.

## المميزات

- **المتجر:** الرئيسية، المتجر مع بحث وفلترة بالأقسام وترتيب بالسعر (يعمل حتى بدون JavaScript)، صفحة لكل منتج، سلة مشتريات، إتمام طلب بالدفع الإلكتروني (مدى، Apple Pay، Visa/Mastercard، STC Pay عبر ميسّر) أو الدفع عند الاستلام، صفحة لمتابعة حالة كل طلب، دليل الرعاية، تواصل معنا.
- **مهيّأ للسوق السعودي:** الأسعار بالريال وشاملة ضريبة القيمة المضافة 15% (مع إظهار قيمة الضريبة)، المناطق الـ13، العنوان الوطني (المدينة، الحي، الشارع ورقم المبنى، الرمز البريدي)، أرقام الجوال السعودية (`05` / `+966`) مع قبول الأرقام العربية ٠-٩، التاريخ الميلادي بتوقيت الرياض، وعرض السجل التجاري والرقم الضريبي في التذييل.
- **لوحة تحكم** على `/admin` لعرض الطلبات والرسائل، محمية بكلمة مرور.
- تصميم متجاوب للموبايل، وضع ليلي تلقائي، رسومات SVG مرسومة بالكود (لا صور خارجية)، خط Cairo مستضاف محليًا.
- SEO: عناوين ووصف لكل صفحة، `sitemap.xml`، `robots.txt`، Web App Manifest.
- إمكانية الوصول: روابط تخطٍّ، تسميات للحقول، رسائل أخطاء مرتبطة بالحقول، احترام `prefers-reduced-motion`.

## الأمان

| الحماية | التفاصيل |
| --- | --- |
| Content-Security-Policy صارمة | `nonce` جديد لكل طلب مع `strict-dynamic` — يمنع XSS وحقن السكربتات (`src/proxy.ts`) |
| Security headers | HSTS، `X-Frame-Options: DENY`، `nosniff`، `Referrer-Policy`، `Permissions-Policy`، COOP/CORP، وإخفاء `X-Powered-By` (`next.config.ts`) |
| الأسعار من الخادم فقط | الخادم يعيد حساب الإجمالي من الكتالوج ويتحقق من المخزون؛ أي سعر قادم من المتصفح يُتجاهل (`src/lib/pricing.ts`) |
| التحقق من المدخلات | Zod على الخادم لكل حقل: أطوال قصوى، رقم جوال سعودي، قائمة مناطق مغلقة، رمز بريدي 5 أرقام، إزالة رموز التحكم و bidi-override (`src/lib/validation.ts`) |
| Rate limiting | حد للطلبات والرسائل ومحاولات دخول الإدارة لكل IP (`src/server/limits.ts`) |
| Anti-spam | حقل honeypot مخفي في النماذج |
| CSRF | Server Actions تقبل POST فقط وتتحقق من `Origin`، والكوكي `SameSite=Strict` |
| جلسة الإدارة | كوكي `HttpOnly` + `Secure` موقّعة بـ HMAC-SHA256 وتنتهي بعد 8 ساعات، ومقارنة كلمة المرور بزمن ثابت (`src/server/session.ts`) |
| الدفع الإلكتروني | العميل يدفع في صفحة ميسّر المستضافة (PCI-DSS) فلا تمر بيانات البطاقة بخادمنا. حالة الدفع لا تؤخذ أبدًا من المتصفح أو من جسم الـ webhook: الخادم يعيد جلب الفاتورة من API ميسّر بالمفتاح السري ويتحقق من رقم الفاتورة والمبلغ بالهللة والعملة قبل اعتبار الطلب مدفوعًا. روابط التحويل مقيّدة بنطاق `moyasar.com`، والـ webhook يتحقق من الـ secret token بزمن ثابت وله حد للحجم والمعدل (`src/server/moyasar.ts`) |
| صفحة الطلب | `/order/[ref]` تتطلب رمز وصول عشوائيًا لكل طلب، وترجع 404 لأي رمز خاطئ حتى لا يمكن تخمين الطلبات |
| فصل كود الخادم | `server-only` يمنع تسريب كود/أسرار الخادم للمتصفح |
| تخزين | ملفات البيانات بصلاحيات `0600` والمجلد خارج git |

## تفعيل الدفع بمدى و Apple Pay (ميسّر)

1. أنشئ حسابًا تجاريًا في [ميسّر](https://moyasar.com) وفعّل وسائل الدفع: مدى، Apple Pay، Visa/Mastercard، STC Pay.
2. ضع المفتاح السري في `MOYASAR_SECRET_KEY` (ابدأ بـ `sk_test_` للتجربة)، واضبط `NEXT_PUBLIC_SITE_URL` على نطاق موقعك (https). هذا المتغير يُضمَّن وقت البناء، فاضبطه قبل `npm run build`.
3. من لوحة ميسّر أضف Webhook على `https://<موقعك>/api/payments/moyasar` لأحداث الدفع، وضع نفس الـ secret token في `MOYASAR_WEBHOOK_SECRET`. الـ webhook يؤكد الطلب حتى لو أغلق العميل المتصفح قبل العودة للموقع.
4. جرّب الدفع ببطاقات الاختبار من وثائق ميسّر، ثم استبدل المفتاح بـ `sk_live_`.

بدون `MOYASAR_SECRET_KEY` يظهر الدفع الإلكتروني معطّلًا ويعمل المتجر بالدفع عند الاستلام فقط.

**مسار الدفع:** إتمام الطلب ← الخادم يحفظ الطلب «بانتظار الدفع» وينشئ فاتورة في ميسّر بالمبلغ المحسوب من الكتالوج ← تحويل لصفحة الدفع ← العودة إلى `/order/[ref]` أو وصول الـ webhook ← الخادم يتحقق من ميسّر مباشرة ويحوّل الطلب إلى «مدفوع». الطلبات غير المدفوعة لا تُحتسب في المبيعات بلوحة التحكم.

## قبل الإطلاق الفعلي

- **قاعدة البيانات:** الطلبات تُحفظ حاليًا في ملفات JSON Lines داخل `DATA_DIR`. هذا مناسب لخادم واحد بقرص دائم (VPS)؛ على Vercel أو أي منصة serverless استبدل `src/server/store.ts` بقاعدة بيانات (Postgres / SQLite) — بنفس الدوال.
- **Rate limiting:** الحالي في الذاكرة لعملية واحدة؛ مع أكثر من instance استخدم Redis (مثل Upstash).
- **IP العميل:** يُقرأ من `X-Forwarded-For` — شغّل الموقع خلف reverse proxy (Nginx / Cloudflare / Vercel) يضبط هذا الهيدر.
- **المنتجات:** في `src/lib/products.ts` — عدّل الأسعار والمخزون والوصف من هناك. رسوم الشحن وحد الشحن المجاني ونسبة الضريبة في `src/lib/pricing.ts`.
- **المتطلبات النظامية:** اضبط `NEXT_PUBLIC_CR_NUMBER` و `NEXT_PUBLIC_VAT_NUMBER` (نظام التجارة الإلكترونية يلزم بإظهارهما)، وتأكد من تراخيص بيع الطيور الحية من الجهات المختصة (المركز الوطني لتنمية الحياة الفطرية / وزارة البيئة)، وأضف سياسة الخصوصية والاسترجاع. لإصدار فواتير ضريبية إلكترونية (فاتورة ZATCA) ستحتاج ربطًا بمزوّد معتمد.
- **الدفع الإلكتروني:** لم يُجرَّب ضد خوادم ميسّر الحقيقية من بيئة التطوير (اختُبر مقابل محاكٍ محلي وباختبارات وحدة)، فنفّذ عملية تجريبية بمفاتيح `sk_test_` قبل الإطلاق. فواتير ميسّر صالحة 24 ساعة.
- استبدل أرقام "عميل سعيد" وغيرها في الصفحة الرئيسية ببياناتك الحقيقية.

## هيكل المشروع

```
src/
  proxy.ts            CSP بـ nonce لكل طلب
  app/                الصفحات + Server Actions (actions/)
  components/         مكونات الواجهة والسلة
  lib/                الكتالوج، التسعير، التحقق، rate limiter (كود مشترك)
  server/             كود الخادم فقط: الجلسات، التخزين، الحدود
tests/                اختبارات Vitest
```
